# KORAVTO CRM — first deployment

Python 3.12 / FastAPI, PostgreSQL 16 + pgvector, Redis + arq, React 18 / TypeScript.
Deployment: <https://erp.korean.parts>. Operational instructions: [deploy/README.md](deploy/README.md).

Implemented: password login with forced first-password change, encrypted settings,
HTTPS/backups, durable inbound and outbound WhatsApp messages, attachments up to 10 MiB,
new conversations by telephone, quotes, internal notes, assignments, human flags,
close/reopen, unread counters, text/phone/order search and manual order references.
Outbound jobs persist in PostgreSQL before sending; HTTP retries reuse a client UUID.
Provider timeouts are retried only inside Wazzup's 60-second deduplication window;
unknown delivery after that window requires an explicit duplicate-risk confirmation.

Tasks are operational: editable boards/statuses/types, Kanban and list, linked chat tasks,
comments, watchers, attachments, immutable history, in-app notifications and assignment reports.
1C customer names and realization numbers are connected through the deployed phone lookup.
Customer profiles, phone identity resolution, merge/split, notes and CSV are operational.
AI drafts, policy-controlled automatic replies and opt-in SMTP/Telegram notifications are implemented.
Detailed 1C order/stock endpoints still require the corresponding 1C service. Historical Wazzup import
requires an actual provider export. This release is not acceptance of the full CRM v1 specification.

## Development

Backend dependencies are pinned in `backend/requirements.lock`; frontend dependencies in
`frontend/package-lock.json`. Run `ruff check`, `mypy app`, `pytest` in backend and
`npm ci && npm run build && npm run lint` in frontend.

Do not commit `.env`, credentials, customer data, dumps, logs or generated administrator passwords.
The repository is public; runtime data and integration credentials remain on the server.

## Клиенты и заказы из 1С

Inbox использует сервис `koravto-1c` (контракт `afbf86b`): `GET /prod/hs/koravto/customers?phone=...`, HTTP Basic Auth. В Настройках → «Клиенты и заказы · 1С» укажите полный адрес сервиса, пользователя и пароль. Пароль зашифрован, доступен только серверу; браузер получает только признак настройки. Запросы идут с API/worker через существующую сеть ZeroTier.

Автоматический поиск выполняется для личных WhatsApp-диалогов при открытии карточки и фоновым обработчиком (не чаще одного запроса за 2 секунды, TTL 15 минут). Кнопка «Обновить из 1С» обновляет досрочно с защитой от повторных запросов в течение 10 секунд. При сбое повтор через минуту; последняя успешная информация сохраняется с отметкой устаревания. Закрытые диалоги без новых сообщений не опрашиваются постоянно.

Один найденный клиент даёт имя в списке и заголовке чата. Несколько совпадений отображаются отдельно, без автоматического выбора: сервис ищет последние шесть цифр в телефонах 1С и не отдаёт уникальный ID контрагента. Номера заказов — строки `realizations` (НомерВКаналеПродаж либо номер реализации 1С); даты, суммы и статусы этот сервис не отдаёт. Порядок, ведущие нули, одинаковые имена и повторяющиеся номера документов сохраняются. Ручные имя чата и привязки заказов не изменяются. Поиск Inbox учитывает сохранённые имена и номера из 1С.

Миграция `0004` добавляет только поля кэша. Недоступность 1С не блокирует переписку. Изменение телефона/настроек подключения скрывает старый результат до нового поиска. Учётные данные, тела ошибок и телефоны не попадают в журналы интеграции.

## Задачи и поручения — 13.11.2026

В меню «Задачи» доступны канбан, список и отчёт «Поручения». Быстрое создание —
заголовок, доска и исполнитель; из карточки чата дополнительно переносятся диалог и
первый ручной номер заказа. Номер T-1001 выдаёт последовательность PostgreSQL; повтор
запроса создания с тем же UUID не дублирует задачу. Карточка открывается по /tasks/T-1001.

Описание поддерживает Markdown без HTML. Есть комментарии с упоминаниями сотрудников,
наблюдатели, метки и вложения до 10 МиБ. Автор неизменяем; изменение задачи требует
её текущую версию, чтобы параллельная правка не затёрла данные. Завершение и повторное
открытие фиксируются в истории. Системные записи в связанном чате клиенту не отправляются.

Администратор настраивает доски, порядок, цвета и завершающие статусы, архивирует доски,
редактирует и отключает типы. При удалении статуса обязательно выбрать другой статус
той же доски: задачи переносятся с историей и уведомлениями. Переключить завершающий
признак занятого статуса нельзя — нужно создать новый и перенести задачи.

Уведомления сейчас **внутри ERP**, в колокольчике: назначение, комментарии, изменение
срока/статуса, завершение и ежедневная просрочка. Настройки tasks.timezone,
tasks.reminder_hour и tasks.workdays определяют час и рабочие дни напоминаний.
На задачу и получателя выдаётся не более одного напоминания за местный день; повтор
после перезапуска безопасен. Email/Telegram-доставка и личные настройки каналов ещё
не подключены. Общая карточка клиента с несколькими телефонами и объединением подключена
в следующем разделе; задачи поддерживают самостоятельную связь с клиентом.

Отчёт агрегирует задачи, созданные в выбранном периоде: автор × исполнитель, всего /
открыто / завершено / просрочено, среднее время до текущего завершения. Администратор
видит всех, остальные — только поручения, где они автор или исполнитель. Клик
открывает точный фильтр списка. CSV экранирует формулы, чтобы пользовательский текст
не выполнялся в таблицах. Время хранится в UTC и показывается в настроенном часовом поясе.

Полная автоматическая проверка запускается в отдельной Docker-сети без production .env:

```sh
docker build -t koravto-crm-api:customers-check-20261113 backend
docker compose -f deploy/docker-compose.verify.yml up --abort-on-container-exit --exit-code-from verify
docker compose -f deploy/docker-compose.verify.yml down
```

Тестовые PostgreSQL и Redis не публикуют порты, сеть internal, PostgreSQL хранится в
tmpfs. Учётные данные в этом файле — исключительно тестовые, рабочие секреты не нужны.
Миграция 0005 добавляет таблицы задач/уведомлений, постоянные ID существующим статусам
и маркер обновления по задаче для диалогов. Содержимое переписки и файлов не меняется.


## Единая карточка клиента — 13.11.2026

Раздел «Клиенты»: поиск по имени/телефону/заказу, фильтры сегмента/страны/тега/открытых
диалогов, CSV. Полная карточка открывается по /customers/UUID; из Inbox есть переход
к той же карточке. Профиль: ручное имя, язык, сегмент, страна, теги, менеджер по умолчанию,
несколько телефонов, ручные номера заказов. Заметки с автором и датой; связь с диалогами
и открытыми задачами. Пользователь staff читает карточки, менеджер/админ изменяет их.

Миграция 0006 связывает существующие личные WhatsApp-диалоги только по валидному
E.164. Совпадение имени не используется. Невалидный номер остаётся в диалоге с отметкой;
его идентичность ограничена каналом и chatId. Группы не превращаются в клиентов.
Новые входящие и первый исходящий используют тот же механизм. Проверенный телефон
здесь означает валидный формат, а не подтверждённое владение номером.

Объединение требует явного подтверждения в интерфейсе и текущих версий обеих карточек.
Основная карточка сохраняет заполненные поля; пустые дополняются, теги/ручные номера
объединяются. Переносятся идентификаторы, диалоги, задачи, заметки и журнал событий.
Старая карточка остаётся ссылкой на основную; повтор запроса безопасен. История задачи
фиксирует перенос. Сообщения и файлы не переписываются и не отправляются клиенту.

Отделение телефона создаёт нового клиента и переносит этот телефон, связанные диалоги
и их задачи. Общие заметки, ручные заказы профиля и задачи без диалога остаются в
исходной карточке; ручные заказы в перенесённых диалогах следуют за диалогами.
Все структурные изменения сериализуются транзакционной блокировкой; конкурентные
создания одинакового телефона не создают дублей. Профиль защищён версией от потери правок.

Текущий сервис 1С по-прежнему отдаёт только имена и номера реализаций. Карточка показывает
сохранённые результаты по каждому телефону и даёт обновить их. Общего стабильного ID
контрагента, сумм, строк и статусов сервис не предоставляет; они не выдумываются.
Язык определяется при первом AI-разборе, если поле клиента ещё пустое; ручное значение сохраняется.
В карточке показаны последние 200 заметок и 100 событий истории; наличие более старых
заметок отмечается. Полное удаление/анонимизация и экспорт переписки — отдельный этап.


## AI и уведомления (13.11.2026)

Настройки → AI: ключ OpenAI, модели, тарифы для консервативной оценки расходов,
режимы по типам и рабочему времени, справочные тексты, коэффициент KRW/USD,
эскалация и версии дополнительного промпта. Все типы по умолчанию — «черновик»;
оплата и претензии никогда не отправляются автоматически. Автоответ на приветствие
требует отдельного включения. При отсутствии ключа виден явный статус, внешний запрос не делается.
Старые переписки при обновлении автоматически в OpenAI не отправляются; можно запустить
черновик кнопкой в конкретном диалоге. Новые сообщения сохраняют задание в той же транзакции.

Отдельный сервис `assistant` (очередь `arq:ai`) обрабатывает OpenAI и уведомления.
Входящие и отправка WhatsApp продолжают работать независимо от доступности OpenAI/SMTP.
Код проверяет язык (`langdetect`, короткие неоднозначные ответы — только на проверку),
запрещённые фразы, точные даты, длину, наличие фактов и лимиты. Перед автоотправкой
повторно проверяются текущее сообщение, ответ менеджера, флаг «нужен человек»,
режим, бюджет и версия промпта. Изменённые/удалённые входящие отменяют старый ответ.
Если отправка уже началась у провайдера, отозвать её гарантированно невозможно.
Неоднозначный результат внешней отправки не повторяется без решения человека.

Имена и номера реализаций из существующего сервиса 1С используются как контекст.
`get_orders/get_order/get_stock` явно возвращают `source_not_connected` для статусов,
остатков и цен; номера реализаций не выдаются за сведения о готовности заказа.
Расчёт цены — формула, а не подтверждение наличия. Google Sheets и Mobis не передаются модели.
Ручные правки сохраняются; только подтверждённо отправленные менеджером пары индексируются
в pgvector (1536 измерений). Примеры используются для стиля, не как текущие бизнес-факты.
Отчёт AI показывает решения по типам и неделям, причины, расходы и ошибки провайдера.
Смена модели требует проверки доступности и тарифа; оценка не заменяет счёт OpenAI.

«Мои уведомления»: Email, подтверждённый личный Telegram, браузер и звук.
Все внешние каналы выключены по умолчанию. После включения отправляются только новые события,
исторические уведомления не рассылаются. SMTP требует STARTTLS или SSL; проверка подключения
не отправляет письмо. Подключение Telegram отправляет одноразовый код по явному нажатию пользователя.
Таймаут после начала SMTP/Telegram-отправки помечается «результат не подтверждён», без слепого повтора.
Неуспешные проверки и попытки доставки видны в журнале. Звук зависит от разрешений браузера.

Проверка: отдельный Compose `deploy/docker-compose.verify.yml`, без production-окружения,
на синтетических данных и с подменёнными внешними API. На сервере с 1 ГБ памяти запускать
сборку, тесты и Chromium последовательно. Перед миграцией 0007 сохранить резервную копию
и образы; откат приложения — на сохранённый release, история AI остаётся в базе.

Документация адаптеров: https://developers.openai.com/api/docs/guides/function-calling,
https://developers.openai.com/api/docs/guides/structured-outputs,
https://core.telegram.org/bots/api. Telegram для клиентов, импорт дампа Wazzup и
полный контракт заказов/остатков 1С остаются отдельными интеграционными этапами.
